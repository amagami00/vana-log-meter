# vana_log_meter（アプリ）

FFXI のチャットログを監視し、戦闘を集計する Flutter アプリ（Windows / macOS）。
解析は `packages/vana_log_core` が担う。

## 使い方

1. 「ログのフォルダ」で `FINAL FANTASY XI\TEMP` を選ぶ。
   選んだフォルダの直下にある `1_*.log` / `2_*.log` だけを読む（サブフォルダは読まない）。
   フォルダが無いとき、選んだウィンドウのログが無いとき、ログが中のフォルダにあるときは、その下に赤字で出す
   （フォルダが無いときは開始できない）。
2. ウィンドウ 1+2 / 1 / 2 を選び、「開始」を押す。1 秒ごとと、ファイルの変更時に読み直す。
   - 1+2（既定）は両方のウィンドウをまとめて読む。両方に出た同じメッセージは 1 回だけ数える。
     ウィンドウごとに戦闘ログを分けていても、両方の戦闘を集計できる。
   - 「開始時に過去のログも読む」をオフにすると、開始より後に出た行だけを集計する。
   - 「ここから集計」を押すと、いまの集計を捨て、その後に出た行だけを数え直す（戦闘の区切りに使う）。
3. 「出力先」を選んでおくと、監視中に読んだ戦闘の事実を 1 秒ごとに CSV（`vana-log-YYYYMMDD-HHMMSS-w<ウィンドウ>.csv`。1+2 は `w12`）へ追記する。
   - 「開始」「停止」「ここから集計」、記録の設定の変更でファイルを区切る。
     「ファイルを区切る」でも区切れる。
   - ウィンドウを切り替えても、読んだ行を読み直したりファイルを区切ったりしない。監視中に選んだウィンドウは
     表示を切り替えた後も読み続け、ウィンドウごとのファイルに追記する。
   - CSV を Excel で開いたままだと書き込めない。書けなかった行は保留し、閉じた後に書く
     （ファイルを区切った後や停止中も書き直す。アプリを終了すると保留中の行は失われる）。
   - 出力先を選ぶ前に読んだ行は CSV に入らない。「開始時に過去のログも読む」で開始すると、
     残っている行を新しいファイルにもう一度書く。
4. 停止中に「CSV を開く…」を押すと、記録した CSV を読み戻し、集計・ログのタブに出す。
   - 開けるのは 1 ファイルずつ。「CSV を閉じる」か「開始」で監視の表示に戻る。
   - 敵味方は記録した時点の判定（`side`・`enemy` 列）を使うので、監視中に見た集計と同じになる。
   - DPS の時刻は `elapsed` 列から戻す。時刻が空欄の行は DPS に入れない（監視中と同じ）。
   - 名前を隠して記録した CSV は、表記（「戦/侍 #1」など）をそのまま出す。「名前を隠す」で付け直さない。

- DPS は戦闘時間 1 秒あたりの与ダメージ。ログの行には時刻がないため、開始後に読んだ行だけで計算する
  （開始前の行だけの人は「–」）。10 秒を超える空白は戦闘の合間として戦闘時間に入れない。
  正確に測るなら「開始時に過去のログも読む」をオフにするか、戦闘の前に「ここから集計」を押す。
- 集計表は「敵」「人」のメニューで絞り込める。どちらも複数選べ、何も選ばなければすべてを出す。
  - 敵のメニューは先頭の入力欄で名前を絞り込める（英字の大小・全角と半角・ひらがなとカタカナを区別しない）。
    選んでいる敵は、絞り込みに合わなくても出す。
  - 複数の敵を選ぶと合算する。DPS の戦闘時間は、同時に戦った時間を重ねて数えない。
  - 敵を選んでいる間、回復は数えない（どの敵にも属さないため）。
  - 人を選ぶと、割合は表示している人の合計に対する割合になる。
- 「集計をコピー」で、いま表示している集計表（絞り込み・名前を隠す設定を反映）をタブ区切りでクリップボードに入れる。
  Excel や Google スプレッドシートにそのまま貼れる。
- CSV の `elapsed` 列は、記録を始めた時刻（「開始」または「ここから集計」を押した時刻）からの秒数。
  開始前から残っていた行は時刻が分からないため空欄になる。
- 「名前を隠す」をオンにすると、敵以外の名前を「ジョブ表記 #番号」に置き換える。
  ジョブ表記は「ジョブ表記」ボタンで名前ごとに入力する。空欄の名前は「PC #番号」になる。
  画面と CSV（`ally` / `enemy` / `actor_name` / `target_name` / `text`）の両方に効く。
  CSV に書いた行の表記は後から変えられないため、切り替えたりジョブ表記を変えたりすると新しいファイルにする。
  魔法だけを受けた敵は敵と判定できず、殴られて敵と分かるまでの行では番号に置き換わる。
- メモリには集計値と直近の行だけを持ち、事実そのものは持たない（長時間記録しても増えない）。
  そのため敵味方の判定は、行を読んだ時点のもので集計する。後から判定が変わっても集計し直さない。
  ログのタブに出すのは直近 2,000 行。
- ゲームはログを 50 行たまるごとにファイルへ書く（ログアウト時などは 50 行未満でも書く）。
  そのため集計への反映は 50 行ずつ遅れ、行の少ないウィンドウほど遅れる。
  1 / 2 を選ぶなら、戦闘の行が多く出るウィンドウを選ぶとよい。
  1+2 では、片方にしか出ない行は、そのウィンドウが書いた時点で集計に入る（ログのタブでも後ろに並ぶ）。
- ゲームは起動のたびに行番号を 0 から数え直す。前回の行が残るファイルに同じ行番号で
  別の内容が書かれたら、新しい行として読む。今回の起動でまだ上書きしていない
  前回のファイルは読まない（過去のログを読むときに前回の行が混ざらないようにするため）。
- 設定（フォルダ・ウィンドウ・過去のログを読むか・CSV に記録するか・ジョブ表記）は次回起動時も残る。

## 開発

```sh
flutter test
flutter build macos   # Windows では flutter build windows
```

- アイコンの元絵は `assets/icon/app_icon.svg`（オリジナルの図案）。変えたら `tool/gen_icons.sh` で
  macOS の PNG と Windows の `.ico` を作り直す（rsvg-convert と ImageMagick が要る）。

## 配布用のビルド

- リリース: `v1.2.3` の形のタグを push すると、両 OS をビルドして GitHub Release に zip を添付する。
  アプリのバージョンはタグの数字になる。

  ```sh
  git tag v0.1.0 && git push origin v0.1.0
  ```

- 試しのビルド: GitHub の Actions タブで `build` を手動実行する（OS は windows / macos / both から選ぶ）。
  成果物の zip は 14 日間残る。

- Windows: zip を展開し、フォルダごと置いて `vana_log_meter.exe` を起動する（exe 単体では動かない）。
  初回は SmartScreen の警告が出るので「詳細情報」→「実行」。
- macOS: zip を展開した `vana_log_meter.app` を右クリック→「開く」。

## 注意

- macOS では App Sandbox を無効にしている（任意のフォルダを読み続けるため）。
- 配布物には署名しない。macOS では初回起動時に右クリック→「開く」が必要。
- Windows の実機では未検証。
